## 50 步 Insight：耗时在哪里

第 11–50 步共 640 个 rank-step 的中位数如下：

| 关键路径 | 时间 |
| --- | ---: |
| Stage | **12.5602 s** |
| Computing | **11.0791 s（88.18%）** |
| Communication Not Overlapped | **0.6284 s（5.00%）** |
| Free | **0.8668 s（6.90%）** |
| HCCL 操作累计 | 1.3158 s |
| Bubble | 0 |

Bubble 为 0 不表示没有空档；流水线气泡、未重叠通信和普通设备空闲是不同字段。A53 与 A54 的 Stage 中位数只差 **3.4 ms（0.027%）**，双机之间没有出现整体节点偏慢。第 34、32、18、20 步通信同步抬升，Computing 则稳定在约 11.08 s，说明剩余波动主要来自通信长尾和设备空档。

设备算子中，MatMulV3 每个 rank-step 累计 **7.497 s**，占 Computing 的 **67.7%**。文本 MLP 为 **4.245 s**，其中 checkpoint 重放 **1.018 s / 68 次**；ViT MLP 与 QKV 分别 **0.947 s、0.358 s**；FA2 前向、反向分别 **0.975 s、0.961 s**。文本 gate/up 大矩阵乘按历史形状与实测时间约达到 **429 TFLOP/s**，耗时主要是因为 token 和权重维度大、次数多，单算子并没有明显“低效到可以重写”的空间。

通信中 **AllReduce 累计 1,278.339 ms/步、398 次/步**，单次 P95 为 **13.762 ms**、最大 **607.178 ms**。AllReduce 的等待为 **1,096.630 ms**、实际 transit 为 **179.677 ms**；最慢 500–600 ms 的单笔调用中等待占比超过 99%。这些长尾与集体同步和 bucket 调度更相关，不能直接判定为链路故障；两机 NPU4 链路均为 `UP` 且历史 down count 为 0。

若现有计算图内完全消除未重叠通信和 Free，理论上可降到约 **10.76 s**，对应有效 MFU 约 **54.8%**；仍低于 60%。所以下一轮应同时处理两条路径：

- 通信：对 ZeRO-2 的 bucket 大小、`overlap_comm` 和 HCCL 确定性开关做独立 A/B，检查 rank 4/12 在慢 step 的同步和 bucket 时间线。
- 计算：逐层增加少量文本层不重算、评估冻结部分 ViT 或减少视觉 token；文本 MLP 重放全部消失的理论上限约 1.018 s，但单个 gate/up BF16 中间结果约 2.09 GB，不能把所有层激活常驻 79.5 GB 峰值附近。
